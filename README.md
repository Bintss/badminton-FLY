# 배드민턴 동아리 운동 투표·대진 앱

카톡 투표 + 현장 즉석 대진을 대체하는 모바일 웹앱.
요구사항 명세서: https://claude.ai/artifact/WkE9RPvrJZMHE2LG3G91Hp

- 프론트: Vite + React + TypeScript + React Router + Tailwind CSS (GitHub Pages 정적 배포)
- 백엔드: Supabase (Postgres, Auth/Kakao, RLS, RPC)
- 원칙: 클라이언트는 **SELECT만** 직접 한다. 모든 쓰기는 권한을 확인하는 `security definer` RPC로 처리한다.

## 1. Supabase 설정

1. Supabase 프로젝트 생성
2. 마이그레이션 적용 (둘 중 하나). `supabase/migrations/`의 파일을 **이름 순서대로** 한 번씩
   - SQL Editor에 각 파일 내용을 붙여넣고 실행 (이미 실행한 파일은 다시 실행하지 않는다)
   - `..._cron.sql` 전에 Database > Extensions에서 **pg_cron**을 켜 둔다 (안 켜도 홈 진입 시 생성되지만 cron이 있으면 아무도 안 들어와도 만들어진다)
   - 또는 CLI: `supabase link --project-ref <ref>` → `supabase db push`
3. Authentication > URL Configuration
   - Site URL: `https://<github-id>.github.io/<repo>/`
   - Redirect URLs: 위 주소 + `http://localhost:5173/`

## 2. 카카오 로그인 설정

1. [Kakao Developers](https://developers.kakao.com)에서 애플리케이션 생성
2. 앱 설정 > 플랫폼 > Web: 사이트 도메인에 `https://<github-id>.github.io`, `http://localhost:5173` 등록
3. 카카오 로그인 > 활성화 ON, Redirect URI: `https://<project-ref>.supabase.co/auth/v1/callback`
4. 카카오 로그인 > 보안 > Client Secret 발급 후 활성화
5. 동의항목: 닉네임(필수)
6. Supabase > Authentication > Providers > Kakao 켜고
   - Client ID = 앱 키의 **REST API 키**
   - Client Secret = 4번에서 발급한 값

> **이메일 동의항목 주의**: 카카오는 비즈 앱이 아니면 이메일(account_email) 동의항목을 받기 어렵고,
> Supabase Kakao provider는 기본적으로 이메일을 요청한다. 로그인 시 이메일 관련 오류가 나면
> ① Supabase Kakao provider 설정에 이메일 없는 사용자 허용 옵션이 있는지 확인하고,
> ② 없으면 카카오 앱을 비즈 앱으로 전환(개인 개발자도 가능)해 이메일 동의항목을 설정한다.
> M0에서 가장 먼저 확인할 항목.

프로필 이름은 카카오 닉네임으로 자동 생성되고, 앱의 `내 정보`에서 바꿀 수 있다.

## 3. 로컬 실행

```bash
cp .env.example .env.local   # Supabase URL, anon 키 입력

npm run dev                  # http://localhost:5173
```

## 4. GitHub Pages 배포

1. 레포를 **public**으로 생성 (무료 플랜 Pages 조건) 후 push
2. Settings > Pages > Source: **GitHub Actions**
3. Settings > Secrets and variables > Actions > **Variables**에 등록
   - `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY` (`sb_publishable_...`, 공개되는 값. RLS가 보호)
   - 예전 이름 `VITE_SUPABASE_ANON_KEY`로 등록했다면 그대로 둬도 동작한다
   - 커스텀 도메인을 쓰면 `VITE_BASE_PATH=/` (기본값은 `/<레포명>/`)
4. main에 push하면 자동 배포. 딥링크 새로고침은 `404.html`(= index.html 복사본)로 처리

**service_role 키는 절대 프론트나 레포에 넣지 않는다.**

### 정기운동 세션 생성 규칙 (M3)

- 템플릿 = 요일 · 시작/끝 · 장소 · 정원 · 코트 수 · 투표 오픈 규칙(N일 전 HH:MM). 운영진이 설정·수정
- 투표 오픈이 7일 이내로 다가온 미래 회차만 만든다. 시각은 동아리 시간대(`clubs.timezone`, 기본 Asia/Seoul) 기준
- 생성 경로 3개(템플릿 저장 직후 · 홈 진입 시 `ensure_upcoming_sessions` · pg_cron 매시 5분), 모두 멱등
- `template_slot`(원래 시작 시각) 유니크 → 운영진이 회차를 옮기거나 취소해도 같은 회차가 다시 생기지 않는다
- 템플릿 수정은 이후 생성분부터. 이미 만든 회차는 일정별로 수정(`update_session`)
- 오픈 시각은 투표가 열리기 전까지만 바꿀 수 있다

### 일정 상세 화면 (M4)

- 오픈 전에는 서버 시각 기준 카운트다운. 남은 시간이 1분 안이면 0.1초 간격으로 갱신하고, 0이 되는 순간 버튼이 켜진다
- 버튼이 켜지는 시점은 화면 표시일 뿐이고, 신청 가능 여부는 항상 서버가 판정한다
- 신청 결과에 서버 왕복 시간(ms)을 표시한다 → 파일럿 때 실제 응답 시간 확인용
- 명단은 Realtime으로 갱신하되, 오픈 순간 이벤트가 몰리므로 기기마다 0.8~1.5초 무작위 지연 후 한 번만 다시 읽는다

### 화면 구성 (UI)

- 하단 탭: 일정 / 대진판 / 내 정보. 대진판 탭은 지금 열 수 있는 운동이 하나면 바로 그 대진판으로 간다
- 운영 메뉴(정기운동 관리, 회원 관리)와 동아리 전환·로그아웃은 내 정보 탭에 있다
- 행동 결과(신청 완료, 오류 등)는 화면 위 토스트로 알린다
- 홈 화면 추가: 안드로이드 Chrome은 메뉴 > 홈 화면에 추가, iPhone Safari는 공유 > 홈 화면에 추가
  - 서비스워커는 앱 파일을 캐시하지 않는다 (배포하면 항상 최신 화면). 오프라인일 때 안내 화면만 보여준다
  - 아이콘은 `python3 scripts/make_icons.py`로 다시 만들 수 있다 (Pillow 필요)
- 대진판을 보는 동안 화면이 꺼지지 않게 한다 (Wake Lock 지원 브라우저: Android Chrome, iOS 16.4+ Safari)

### 동아리 정보

- 운영진: 내 정보 > 동아리 정보 수정에서 로고, 이름, 소개(1000자), 연락 링크(https), 운동 장소(이름·주소·메모)
- 모두: 상단 동아리 이름을 누르면 소개 화면 (정기운동 요일·시간, 장소별 카카오맵 링크, 연락 링크)
- 가입 전 동아리 목록에서도 로고·소개·장소·링크가 보인다
- 로고는 화면에서 가운데 기준 정사각형 512px로 줄여 `club-logos` 버킷에 `<club_id>/logo-<시각>.webp`로 올린다.
  버킷은 공개 읽기, 업로드·삭제는 그 동아리 운영진만 (Storage 정책)
- 번개 만들기·정기운동 등록의 장소 칸에 등록된 장소가 버튼으로 나온다

### 대진판 (M5)

- 일정 상세에서 운동 3시간 전부터 끝나고 3시간까지 `대진판 열기`가 보인다
- 조작은 그 운동의 참석 확정자와 운영진만. 그 외 회원은 보기만
- 참석자 목록은 도착한 사람 → 게임 수 적은 순 → 오래 쉰 순. 30분 이상 쉰 사람은 노란색
- 쉰 시간 = 지금 − max(마지막 경기 종료, 체크인). 늦참은 도착 체크인부터 세서 손해 보지 않는다
- 4명을 눌러 경기 만들기. 이미 경기 중이거나 대기 경기에 있는 사람이 있으면 경고 1회, 다시 누르면 진행
- 빈 코트가 있으면 새 경기가 바로 들어가고, 경기를 종료하면 대기 1번이 그 코트로 자동 진입
- 종료·취소 버튼은 실수 방지로 두 번 눌러야 실행 (3초 안)
- 모든 대진 RPC는 세션 행을 잠그고 처리 → 여러 폰에서 동시에 눌러도 코트 중복 배정·순서 꼬임 없음
  (로컬 검증: 10명이 동시에 경기 생성 → 코트 2면 각 1경기 + 대기 8경기 순번 중복 없음,
  같은 경기를 8대가 동시에 종료 → 2경기만 종료, 대기 2경기 정확히 진입)
- 참석 취소한 사람이 이미 대기 경기에 들어가 있으면 그 경기는 그대로 남는다 → 필요하면 경기를 삭제하고 다시 만든다

### 자체대회 (T1)

- 홈 → `+ 자체대회`(운영진만) → 운동 정보와 대회 설정(매치 수, 점수, 경기당 시간)을 한 번에 정해 만든다. 처음 상태는 **대진 준비 중(draft)**. 참석은 선착순 투표
- 일반 운동을 대회로 바꾸는 기능은 없다. 대회를 그만두려면 운동 취소
- 대진 짜기 → `자동으로 짜기`: 매치마다 min(코트 수, ⌊참석자/4⌋)경기
  - 출전자는 지금까지 게임 수가 적은 사람부터 → 모두 ±1 안에서 같은 게임 수. 같으면 직전 매치에 쉰 사람 먼저
  - 묶기는 비용 최소화(무작위 시작 + 두 자리 맞바꾸기 국소 탐색 12회): 파트너 반복 > 두 팀 실력 합 차 > 상대 반복 > 한 경기 안 실력 폭
  - 실력 점수는 급수에서: A조 5, B조 4, C조 3, D조 2, 초심 1, 미입력·게스트 3
  - 급수는 목록(A조·B조·C조·D조·초심)에서 고른다. 본인은 내 정보, 운영진은 회원 관리에서. DB 제약으로 목록 밖 값은 저장 불가 (기존 자유 입력 값은 마이그레이션에서 같은 규칙으로 맞추고, 알아볼 수 없는 값은 비움)
  - 로컬 측정: 30명·6코트·5매치 → 전원 4게임, 파트너 반복 0, 팀 실력 합 차 최대 1, 0.1초
- 성별(남/여): 회원은 내 정보에서 본인이 입력, 운영진은 회원 관리나 대진 짜기 화면에서 수정. 게스트는 추가할 때 고른다
  - 참석자 모두 성별이 있으면 모든 경기가 남복·여복·혼복(팀마다 남1·여1) 중 하나. 출전 남녀가 각각 짝수가 되게 출전자를 고르고, 가능한 종목 조합을 모두 시도해 비용이 가장 낮은 것을 쓴다. 같은 종목을 반복하면 비용이 붙어 골고루 섞인다
  - 일부만 성별이 있으면 자동 짜기 전에 나머지를 정하라고 안내. 아무도 없으면 성별 없이 짠다
  - 여자(또는 남자)가 홀수면 그쪽은 매치마다 한 명이 쉬어야 해서 게임 수가 ±1을 넘을 수 있다. 1명뿐이면 자동 대진에 들어가지 못한다 (안내 후 직접 넣기)
  - 로컬 측정: 30명(여10)·6코트·5매치 → 남복 13·혼복 14·여복 3, 전원 4게임, 파트너 반복 0, 한 종목만 한 사람 0
- 고치기: 매치 탭을 고르고, 사람을 누른 뒤 다른 사람·빈 자리·쉬는 사람을 누르면 자리가 바뀐다. 경기마다 `실력 5 : 6`, `파트너 반복`, 쉬는 사람엔 `연속 휴식` 표시. 사람별 게임 수는 실시간 (2게임 이상 적으면 노란색)
- 저장해도 확정 전에는 운영진만 본다 (RLS). `확정하고 공개`를 누르면 참가자 모두에게 바로 공개
- 확정 후 대진판은 대회 경기만 돌린다: 자율 경기 만들기 막힘, 대기 중이던 자율 경기는 정리, 진행 중이던 자율 경기는 끝까지
- 코트 배정: 경기마다 코트가 정해져 있다 (매치의 n번째 경기 → 코트 n, 경기가 코트보다 많으면 돌아가며). 코트가 비면 **그 코트의** 다음 경기 중 **4명 모두 참석 확정 + 도착 + 다른 코트에서 경기 중이 아닌** 경기가 들어간다. 다른 코트 경기를 끌어오지 않는다
- 대회 경기 취소·선수 교체·확정 취소·대회 끝내기는 운영진만. 대회 경기 순서는 바꿀 수 없다
- 대회 중 참석 취소 허용. 그 사람이 든 경기는 건너뛰며 "선수를 바꿔야 해요"로 표시
- 마지막 대회 경기가 끝나거나 운영진이 대회를 끝내면 자동으로 자율 대진으로 돌아간다
- 설정 잠금: 매치 수·대회 켜기/끄기는 확정 전까지, 점수 규칙은 첫 점수 입력 전까지(T2), 경기당 시간은 언제나

### 대회 점수 (T2)

- 대진판에서 대회 경기의 `경기 종료 · 점수` → 점수 입력 창. `점수 저장하고 경기 종료` 또는 `점수 없이 경기 종료 (나중에 입력)`. 코트는 점수와 상관없이 비울 수 있다
- 점수 규칙(목표 T, 최대 U): 이긴 팀 ≥ T. T에서 끝나면 2점 이상 차(25:24 거부), 듀스 뒤엔 정확히 2점 차, U에 도달하면 1점 차도 인정(30:29). U 초과 불가. 앱과 서버(`score_problem`)가 같은 규칙
- 권한: 그 경기 선수 4명 + 운영진. 대회가 끝난 뒤엔 운영진만 수정(점수가 아직 없는 경기는 선수도 입력 가능)
- 대진표에서 끝난 경기를 누르면 점수 입력·수정. 수정할 때 마지막으로 본 입력 시각을 같이 보내서 그사이 다른 폰이 바꿨으면 거부(`score_conflict`)
- 기권: 점수 창의 `기권으로 기록`(친 뒤 기권), 운영진의 대기 경기 `기권`(끝내 안 옴 → 치지 않고 끝, 게임 수에 안 들어감)
- 대진표: 점수(이긴 쪽 강조), 기권승, 점수 미입력 개수. 내 대회 경기 카드에 승패
- 모든 입력·수정은 activity_log에 이전 값과 함께 남는다
- 첫 점수가 들어가면 점수 규칙(목표·최대 점수)은 바꿀 수 없다

### 대회 명단 관리 (T3)

- 대회 화면의 `참가자 명단` → `명단 관리`(운영진, 대회가 끝나기 전까지)
  - `회원 추가`: 신청 안 한 회원을 바로 참석 확정. 정원이 차 있으면 정원 +1 (변경 이력에 남김)
  - 대기자 `확정`: 정원과 상관없이 바로 확정 (정원 +1)
  - `빼기`: 참석 취소와 같음. 확정자를 빼면 대기 1번 자동 확정. 그 사람이 든 시작 전 대회 경기 수를 알려줌
  - `게스트 추가`: 이름·성별·급수. 도착 처리는 안 함 (대진판의 게스트 추가와 다름)
- 대진을 짠 뒤 새로 들어온 사람이 있으면 대진 짜기에 `명단이 바뀌었어요` 안내
- 대진 확정 후 참석 취소 확인 창에 `대회 경기 n개에 들어 있어요`. 그 경기는 선수 교체 전까지 코트에 안 들어감
- 선수 교체 후보는 대회 경기가 적은 사람 → 빠지는 사람과 실력이 비슷한 사람 순

### 알림 (웹 푸시 + 앱 안 알림함)

| 종류 | 받는 사람 | 시점 |
|---|---|---|
| 가입 신청 | 그 동아리 운영진 | 가입 신청이 들어왔을 때 |
| 가입 승인 | 신청한 본인 | 승인됐을 때 |
| 새 운동 투표 | 동아리 회원 전체 (만든 사람 제외) | 정기운동 자동 생성(투표 오픈 7일 전)·번개·자체대회가 생겼을 때 |
| 투표 10분 전 | 동아리 회원 전체 | 투표 오픈 10분 전 (매분 도는 예약 작업) |
| 코트 배정 | 그 경기의 회원 선수 | 내 경기가 코트에 들어갔을 때 (자율·대회) |
| 코트 대기 | 그 경기의 회원 선수 | 자체대회에서 내 경기가 그 코트의 바로 다음 차례가 됐을 때 (앞 경기 시작 시점, 경기마다 한 번) |

- 모든 알림은 앱 안 알림함(헤더의 종)에 쌓이고, 알림을 켠 기기에는 웹 푸시로도 간다
- 내 정보 → 알림에서 기기 알림 켜기/끄기, 받을 종류 고르기 (계정 기준)
- 아이폰은 사파리에서 "홈 화면에 추가"한 앱에서만 푸시 가능 (iOS 16.4+). 카카오톡 안 브라우저는 푸시 불가 → 알림함으로 확인
- 알림 저장이 실패해도 가입·운동 생성·코트 배정 같은 원래 작업은 그대로 진행된다
- 흐름: 이벤트 → `notifications` 행 → DB 트리거가 `pg_net`으로 Edge Function `send-push` 호출 → 웹 푸시. 매분 예약 작업이 10분 전 알림을 만들고 못 보낸 푸시를 다시 보낸다

#### 알림 설정 (처음 한 번, 운영자)

1. SQL Editor에서 `supabase/migrations/20261118010000_notifications.sql` 실행
2. Database → Extensions에서 **pg_net**, **pg_cron** 켜기. 1번보다 나중에 켰다면 SQL Editor에서 한 번 더:
   ```sql
   select cron.schedule('notifications-tick', '* * * * *', 'select public.notifications_tick()');
   ```
3. 키 만들기 (내 컴퓨터 터미널)
   ```bash
   npx web-push generate-vapid-keys      # Public Key, Private Key가 나온다
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"   # PUSH_SECRET으로 쓸 임의 문자열 (윈도우에서도 됨)
   ```
4. Edge Function 배포 (레포 폴더에서)
   ```bash
   npx supabase login
   npx supabase link --project-ref <프로젝트 ref>     # 대시보드 주소 /project/<ref>
   npx supabase secrets set VAPID_PUBLIC_KEY=<Public Key> VAPID_PRIVATE_KEY=<Private Key> VAPID_SUBJECT=mailto:<운영진 메일> PUSH_SECRET=<3번 임의 문자열> APP_URL=https://bintss.github.io/badminton-FLY
   npx supabase functions deploy send-push --no-verify-jwt
   ```
   (secrets set은 한 줄로. Docker가 없어도 배포된다. 터미널 대신 대시보드로 하는 방법: Edge Functions → Deploy a new function → Via Editor, 이름 `send-push`, `supabase/functions/send-push/index.ts` 내용 붙여넣기 → 배포 후 JWT 검증 끄기, 비밀값은 Edge Functions → Secrets)
   Private Key와 PUSH_SECRET은 저장소·앱 코드에 넣지 않는다 (Supabase 비밀값에만)
5. SQL Editor에서 DB가 함수를 부를 수 있게 Vault에 저장
   ```sql
   select vault.create_secret('https://<프로젝트 ref>.supabase.co/functions/v1/send-push', 'push_function_url');
   select vault.create_secret('<3번 PUSH_SECRET>', 'push_secret');
   select vault.create_secret('<Public Key>', 'vapid_public_key');   -- 공개 키 (앱이 읽어감)
   ```
6. 확인: 앱 → 내 정보 → 알림 켜기. 그다음 SQL Editor에서 나에게 테스트 알림
   ```sql
   select public.notify((select id from auth.users where email = '<내 카카오 메일>'), null, null, 'vote_created', '테스트 알림', '알림이 잘 와요', '/clubs');
   ```
   폰에 알림이 오면 끝. 안 오면 `select id, push_error, pushed_at from notifications order by id desc limit 5;`와 Edge Functions → send-push → Logs 확인

### 회원 내보내기·강퇴, 동아리 나가기·삭제

- 회원 관리 → 회원 줄의 `관리`: 운영진 지정/해제, **내보내기**(다시 가입 신청 가능), **강퇴**(다시 신청 불가)
- 운영진은 바로 내보낼 수 없다(먼저 운영진 해제). 본인도 내보낼 수 없다(동아리 나가기 사용)
- 내보내기·강퇴·나가기 모두 아직 시작 안 한 운동의 참석·대기 신청을 취소하고 빈자리는 대기자 승격. 지난 운동·경기 기록은 남김
- 가입 신청자는 `다시 신청 못 하게 거절`로 강퇴할 수 있다. 강퇴한 사람 목록에서 `해제`하면 다시 가입 신청 가능 (자동 가입은 아님)
- 내 정보 → `동아리 나가기`. 마지막 운영진은 다른 사람을 운영진으로 지정한 뒤에 나갈 수 있다
- 동아리 정보 수정 맨 아래 → `동아리 삭제`: 동아리 이름을 똑같이 입력해야 켜진다. 로고 파일을 먼저 지우고, DB에서 동아리를 지우면 운동·신청·경기·기록·회원이 모두 함께 지워진다 (되돌릴 수 없음)

### 투표 동시성 설계 (M2)

- 신청·취소·정원 변경은 모두 **세션 행을 `FOR UPDATE`로 잠근 뒤** 처리 → 같은 운동에 대한 요청은 한 줄로 서서 하나씩 처리된다
- 오픈 판정은 `now()` = 서버가 요청을 받은 시각. 단말 시계와 무관
- 접수 순서 = `seq` (서버 처리 순서). 확정/대기 순번은 이 값으로 계산
- 확정자가 취소하거나 정원이 늘면 같은 트랜잭션에서 대기 1순위부터 승격
- 정원은 회원 신청만 센다 (게스트 제외). 같은 사람이 동시에 여러 번 눌러도 신청은 1건

### 동시 신청 테스트 결과 (로컬 2코어 컨테이너, pgbench)

| 시나리오 | 결과 | DB 처리 지연 |
| --- | --- | --- |
| 서로 다른 100명 동시 신청, 정원 30 | 확정 30 / 대기 70, 초과 0, 순서 역전 0 | p50 317ms, p95 471ms |
| 50명이 각자 2번씩 동시 신청 | 신청 50건만 생성, 중복 0 | p95 465ms |
| 확정자 20명 취소 + 신규 40명 신청 동시 | 확정 30 유지, 승격 20명 = 기존 대기 1~20순위 | p95 303ms |

- 지연은 100건이 한 줄로 처리되는 대기 시간이 대부분이다. 1건 처리는 약 1.6ms(연결 재사용 시)
- 이 값에는 **네트워크가 빠져 있다.** 실제 p95(목표 1초 미만)는 M4 투표 화면이 나온 뒤 실서버에서 측정한다
- Supabase 프로젝트 리전은 **Northeast Asia (Seoul)** 권장 (리전은 프로젝트 생성 후 변경 불가)

## 6. 첫 사용 흐름

1. 운영진이 카카오 로그인 → `동아리 만들기` (만든 사람이 첫 운영진)
2. 회원들은 로그인 → 동아리 목록에서 `가입 신청`
3. 운영진이 홈 > `회원 관리`에서 승인
4. 회원은 `내 정보`에서 이름·급수 입력

현재는 로그인한 누구나 동아리를 만들 수 있다 (다른 동아리 확장 대비). 막고 싶으면 `create_club` 권한을 조정한다.
